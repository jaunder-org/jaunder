# Spec — issue #635: second convergence pass on session/user test fixtures

**Issue:** jaunder-org/jaunder#635 (`dx`, Task). Follow-up to #626. **Kind:**
Pure test-only refactor. No production code, no behaviour change.

## Problem

#626 introduced the seeding fixtures but left two systematic noise sources (full
inventory in the issue): every seed still picks an arbitrary username the test
usually never reads, and tests bind single-use copies of returned struct fields
(`let user_id = session.user_id;`). Survey scale: ~520 seed sites, of which
79–92% never reference the name.

## Design

### Usernames are autogenerated; the only reference path is `.username`

No test passes a username literal **for a user it seeds**. The fixtures generate
a unique valid name and expose it on their return value.

- **Mechanism:** a process-wide `static SEED_SEQ: AtomicU64` in
  `storage::test_support`; each seed with no explicit name takes
  `parse_username(&format!("user{n}"))` (n = `fetch_add(1, Relaxed)`).
  `Username` is non-empty `[a-z0-9_-]` (verified — no length bound), so
  `user{n}` is always valid. Fully encapsulated: the `static` is private; test
  call sites never see it (`SeedUser::new().seed(&state)`).
- **Correctness invariant (document on `SeedUser`):** the counter is correct iff
  every `SeedUser`-using test runs against a **fresh, per-test database** —
  which holds structurally: `SeedUser` only takes a `TestEnv`/`Backend::setup()`
  `AppState` (fresh SQLite tempdir / fresh Postgres clone per test,
  ADR-0033/0053), and the one shared-DB context (e2e) seeds through the separate
  `test-support` _crate_ path, never `SeedUser`. Under nextest
  (process-per-test) the counter restarts at 0 per process, so within a test
  names are deterministic (`user0, user1, …`); across tests there is no shared
  state. If the invariant were ever violated (two counters-from-0 writing one
  DB), the second `create_user` returns `UsernameTaken` → `seed()` panics — a
  **loud** failure, never silent corruption. `SeedUser`'s doc comment states
  this requirement.
- **Accepted trade-off:** some storage seeds use _descriptive_ literals
  (`multi_tag_user`, `cursor_test_user`) that the test never reads — autogen
  replaces them with `user{n}`, losing a documentation-only hint. This is
  intentional (the name is unread; the test's own fn name documents intent) and
  in line with the autogenerated-only principle.
- **No `.username()` override.** The survey's two "mismatch" cases don't seed a
  named user — they reference a _non-seeded / wrong_ name: `atompub_service`
  auths as `"mallory"` against a real user's collection (`!= session.username` →
  401), and `feed_handlers` requests `/~charlie/` (a nonexistent feed) while a
  normal user is seeded. Those literals stay as plain string literals; they are
  not seed calls, so the autogen principle holds. (If implementation surfaces a
  genuine need to seed a _specific_ name, add `.username(&str)` then — not
  speculatively, per the coverage gate.)

### `SeedUser` returns a struct (chosen: uniform API)

```rust
// storage::test_support
pub struct SeededUser { pub user_id: UserId, pub username: Username }

pub struct SeedUser<'a> { /* password, display_name, is_operator — NO username */ }
impl<'a> SeedUser<'a> {
    pub fn new() -> Self;                       // autogenerated username
    pub fn password(self, &'a str) -> Self;
    pub fn display_name(self, &'a str) -> Self;
    pub fn operator(self) -> Self;
    pub async fn seed(self, &Arc<AppState>) -> SeededUser;   // was -> UserId
}
```

`seed()` now returns `SeededUser`, so the ~191 sites that used its result as a
bare `UserId` change to `.user_id`
(`PostCreation { user_id: user.user_id, .. }`,
`seed_posts(&state, user.user_id, ..)`). Uniform: one terminal, one struct. (A
`Deref<Target=UserId>` was rejected — by-value `UserId` args don't auto-deref,
so it wouldn't remove the churn.)

`SeedUser::new()` takes no args and is hand-written (`password: "password123"`,
`display_name: None`, `is_operator: false`). **Not** `#[derive(Default)]` —
`&str`'s `Default` is `""`, which would silently wipe the password default.

### Session fixtures gain `username`

```rust
pub struct SeededSession { pub user_id: UserId, pub username: Username, pub token: RawToken }
impl SeededSession { pub fn cookie(&self) -> String; }

pub async fn create_user_and_session(&Arc<AppState>) -> SeededSession;      // was (state, username)
pub async fn create_operator_and_session(&Arc<AppState>) -> SeededSession;  // was (state, username)
pub async fn create_session_for(&Arc<AppState>, user_id: UserId) -> SeededSession;
```

- `create_user_and_session` / `create_operator_and_session` drop the username
  param; they seed via `SeedUser` (which yields the generated `username`) and
  **construct the `SeededSession` directly** with that known username + the new
  token — they do NOT delegate to `create_session_for` (which would redundantly
  re-look-up the name they already hold).
- `create_session_for` takes only `user_id` (a session on an _already-seeded_
  user), so it looks the username up (`state.users.get_user(user_id)`) to keep
  the invariant that `SeededSession` always carries a `username`. Its ~5 callers
  are second-session/display-name tests that don't read `.username`; the lookup
  is a cheap test-only query.
- The `username` field is the typed `Username` (Deref→`str`, `Display`,
  `PartialEq<&str>`/`PartialEq<Username>` from the newtype trailer), so
  name-referencing sites work directly:
  `format!("/atompub/{}/posts", session.username)`,
  `get_user_by_username(&session.username)`,
  `assert_eq!(record.username, session.username)`. One caveat: `str::contains`
  is generic over `Pattern`, which does NOT Deref-coerce `&Username`, so a
  substring check spells it `session.username.as_str()` (no current test does
  contains-on-a-username, but note it).

### Mirror-variable bindings inlined

Single-use `let x = <fixture>.user_id / .token / .cookie();` collapse to inline
`<fixture>.user_id` etc. Bindings used 3+ times, or that wrap a side-effectful
call (e.g. `token_b = create_session_for(...).token`), stay.

**The id+name boundary (implementer trap):** a `SeededUser`/`SeededSession` that
feeds BOTH an id and the name into one test (e.g. `storage/mod.rs` sites that
seed then do `get_user_by_username(&user.username)` or
`assert_eq!(rec.username, user.username)` _and_ use `user.user_id`) is **two
uses** → the struct **stays bound**. The inline-single-use rule (above) applies
only when the struct's field is read exactly once. Do not inline-and-drop a
struct whose name a later line still needs — that's the easy mistake.

### Local wrapper helpers deduped

Fold the per-file seed→cookie wrappers into the shared fixtures now that names
are autogenerated: `web_account::operator_cookie` (its `username` param goes
dead → `create_operator_and_session(&state).cookie()`),
`web_media::authed_cookie` (and its un-helpered duplicate in
`media_handlers.rs`), `audiences`/`web_subscriptions` `make_user`/`cookie_for`.
Where a one-liner shared helper already covers it, delete the local wrapper and
call the shared one.

## Out of scope (filed as separate issues — plan's first task)

- **`seed_post(&state, user_id, title)` fixture** — ~50 repeated `PostCreation`
  / `CreatePostInput` blocks. Post-seeding, a distinct concern.
- **`post_*` helpers taking `Arc<AppState>` by value** → pervasive
  `Arc::clone(&state)` / `mailer.clone() as Arc<dyn MailSender>`. A signature
  change, not seeding.
- **HTTP-wire username literals** in `web_auth.rs` register/login/lookup request
  bodies and `web_email`'s `email=` body — payloads, not seeds.
- The bespoke #626 carve-outs stay bespoke: error-path `create_user`
  (duplicate/hash), `create_user_with_invite`, label-asserting `create_session`.
  Where these hardcode a name that just round-trips, they MAY read a generated
  name if convenient, but are not required to (they bypass `SeedUser`).

## Special cases the implementation must handle

- **Raw-SQL name references** — `storage/src/users.rs:669,689,712` bake the
  username into a SQL string (`WHERE username='testuser'`) in auth-error tests.
  These seed via a bespoke path (not `SeedUser`); keep them as-is with their
  literal, or if seeded via `SeedUser`,
  `format!("… WHERE username='{}'", user.username)`.
- **`storage::test_support::seed_user`?** Already removed in #626 — n/a.

## Acceptance criteria (observable)

1. **No seed passes a username literal.** `rg` for a string literal argument to
   `SeedUser::new` / `create_user_and_session` / `create_operator_and_session`
   returns nothing (those calls are now arg-less). Remaining username string
   literals in tests are only: the two mismatch/non-seeded names
   (`atompub_service` `"mallory"`, `feed_handlers` `"charlie"`), the enumerated
   bespoke carve-outs, and `web_auth`/`web_email` wire-body payloads.
2. **`SeededUser` / `SeededSession` expose `username`**, and every name-
   referencing site (~47) reads it from the struct rather than a literal.
3. **No single-use mirror-variable binding** of a returned struct field remains.
4. **Local seed→cookie wrapper helpers are gone**, replaced by the shared
   fixtures.
5. **Behaviour preserved.** `cargo xtask validate` green. Only `#[cfg(test)]`
   modules and the feature-gated `storage/src/test_support.rs` change; no
   non-test code path.
6. **New fixture API documented**; clippy clean (every builder method + the new
   struct fields have real callers — coverage gate).
