# #995 — pin Rust 1.97.1

Issue: [#995](https://github.com/jaunder-org/jaunder/issues/995). Milestone:
Developer tooling & DX.

## Summary

Jaunder names Rust's mutable `stable` channel in `rust-toolchain.toml` while
`flake.nix` fixes the fetched channel manifest by content hash. When stable
advanced from 1.95.0 to 1.97.1, clean Nix evaluators fetched new bytes under the
same channel URL and rejected them against the old hash. Cached evaluators
continued using 1.95.0, so the failure depended on store state and eventually
ejected PR #957 from the merge queue.

Accept Rust 1.97.1 explicitly. The repository will name the immutable release
and its matching manifest hash, then migrate the five equality assertions
rejected by the release's new `clippy::manual_assert_eq` warning.

## Decisions

| ID     | Decision                                                                                                                                                                                                                     |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D1** | Set `rust-toolchain.toml`'s channel to the exact release `1.97.1`; do not retain the mutable `stable` name. Future compiler adoption requires an explicit version-and-hash change.                                           |
| **D2** | Set `flake.nix`'s `fenix.fromToolchainFile` manifest hash to `sha256-A1abGIbOtcBSdrUMhDGrER3pRM1hQP4fp9gh3Y4PKc8=`, the Rust 1.97.1 manifest hash. The existing Fenix and nixpkgs lock inputs remain unchanged.              |
| **D3** | Replace the five equality-shaped `assert!` calls identified by Rust 1.97.1 Clippy with `assert_eq!`. Do not suppress `clippy::manual_assert_eq`.                                                                             |
| **D4** | Keep the toolchain pin and required Clippy migration in one atomic change: the pin alone fails the repository's warning-denying lint gate.                                                                                   |
| **D5** | Add no runtime tests, changelog entry, domain documentation, or ADR. This changes development/build inputs and mechanically preserves existing test assertions; it changes no Jaunder runtime contract or domain vocabulary. |

## Acceptance criteria

- **AC1 — immutable compiler selection.** `rust-toolchain.toml` names channel
  `1.97.1`, and the resulting compiler reports Rust 1.97.1.
- **AC2 — matching Nix manifest.** `flake.nix` contains the 1.97.1 manifest hash
  `sha256-A1abGIbOtcBSdrUMhDGrER3pRM1hQP4fp9gh3Y4PKc8=`; the existing pinned
  Fenix revision can construct the complete configured toolchain, including the
  Wasm target and requested components.
- **AC3 — warning-free assertions.** The three affected assertions in
  `macros/tests/str_newtype.rs` and two in `common/src/render.rs` use
  `assert_eq!`; no lint suppression is introduced; Rust 1.97.1 host Clippy
  passes with `-D warnings`.
- **AC4 — all compiler surfaces pass.** Rust 1.97.1 formatting, host Clippy,
  Wasm Clippy, `tools/` Clippy, and `xtask/` Clippy pass under their
  repository-defined arguments.
- **AC5 — shipping gate passes.** `cargo xtask validate` completes successfully,
  including coverage and all four backend/browser end-to-end combinations.

## Risks

- Rust 1.97.1 may expose compiler, formatter, or lint changes beyond the five
  already identified. The complete static and shipping gates are authoritative;
  any additional failures caused by the new compiler are fixed in this issue
  rather than suppressed.
- Exact release pins intentionally stop silent compiler movement. A later Rust
  release requires another explicit reviewed update.
