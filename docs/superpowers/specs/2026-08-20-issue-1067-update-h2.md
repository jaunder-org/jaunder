# #1067 — update locked `h2` past RUSTSEC-2026-0258

Issue: [#1067](https://github.com/jaunder-org/jaunder/issues/1067). Milestone:
Developer tooling & DX.

## Problem

`Cargo.lock` resolves transitive HTTP/2 dependency `h2` at 0.4.14. `cargo-deny`
rejects that version for RUSTSEC-2026-0258 (unbounded empty DATA frames), so the
host check gate cannot complete. `hyper` 1.9.0 is the lockfile consumer; no
workspace manifest directly pins `h2`.

## Decisions

| ID     | Decision                                                                                                                                                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D1** | Run `cargo update -p h2` and commit only its resulting lockfile changes. A dry run resolves 0.4.14 to 0.4.17, which is newer than the advisory's 0.4.16 minimum.                                                                                  |
| **D2** | Do not edit any `Cargo.toml`, application source, cargo-deny configuration, or advisory-ignore list. The existing semver constraint already permits the safe patch release, so a manifest change would broaden scope without changing resolution. |
| **D3** | Verify the changed lock package is `h2` 0.4.17 and that `cargo xtask check --no-test` passes cargo-deny. No ADR or `CONTEXT.md` change is needed: this is a routine transitive lockfile security update, not a durable architectural decision.    |

## Acceptance criteria

- **AC1 — safe resolution.** `Cargo.lock` resolves the sole `h2` package to
  version 0.4.17 or a later cargo-deny-accepted non-vulnerable release.
- **AC2 — minimal delta.** The committed dependency change is limited to the
  `h2` lockfile package version/checksum; no manifest, application source, or
  cargo-deny advisory policy changes.
- **AC3 — gate proof.** `devtool run -- cargo xtask check --no-test` completes
  successfully, including cargo-deny's advisory step.

## Risks

- **Registry resolution changes during implementation.** If `cargo update -p h2`
  resolves a release other than 0.4.17, accept it only when cargo-deny accepts
  it and the lockfile delta remains limited to `h2`; otherwise stop and
  investigate the extra resolution change.
