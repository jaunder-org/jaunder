Normal dependency advisory checks accept the corrected dependency graphs,
unblocking delivery currently stopped by RUSTSEC-2021-0157 without bypassing
security policy. Existing Post body and Rendered Title sanitization behavior
remains intact.

Issue: https://github.com/jaunder-org/jaunder/issues/1760

Authorized delivery branch: `herdsman/work-b7c108c0` in the assigned checkout.
The issue token identifies this contract; it does not authorize a branch rename.

## Load-bearing decisions

- Manager approved a unified ammonia **4.2.3** correction across the root,
  tools, and xtask workspaces. This supersedes the 4.1.7 candidate.
- Raise the root workspace declaration's minimum to `4.2.3`, following the
  existing caret-version convention; do not introduce an exact-version pin.
- Precisely resolve ammonia **4.2.3** in `Cargo.lock`, `tools/Cargo.lock`, and
  `xtask/Cargo.lock`; no affected ammonia copy may remain in these graphs.
- These are independent Cargo workspaces. A root lock update alone cannot
  establish the tools or xtask result (ADR-0141).
- Accept only transitive changes required to resolve the approved version.
  Review every changed package against the affected graph; no blanket update.
- Ammonia 4.2.3 requires cssparser 0.38 and html5ever 0.40. Existing direct
  parser consumers may still need html5ever 0.39; do not force those consumers
  onto a new parser API or remove still-reachable versions merely for dedup.
- Correct the root manifest's parser-correspondence comment if the approved
  resolution makes its claim untrue; do not misdescribe independent parsers.
- Preserve production sanitizer builders, allowlists, style policy, URL policy,
  trusted provider assembly, and common-owned sanitized-value construction.
- No production `filter_style_properties` use or explicit style allowance was
  found. Advisory presence is proven; application exploitability is not.
- Body and title style-removal assertions exercise Jaunder's actual sanitizer
  policies. They are compatibility/policy tests, not upstream exploit repros.
- Preserve host-only sanitizer feature boundaries; lock reachability alone must
  not be described as execution in CSR (ADR-0079).
- Persisted rendered bytes retain existing decode and read behavior. No implicit
  re-sanitizing-on-read, backfill, or migration is part of this correction.
- Normal advisory checks must run for all three workspaces, using the existing
  deny policy and without advisory skips, ignores, or disabled fetching.
- Sandbox checks intentionally omit advisories (ADR-0145), so their success
  cannot substitute for the normal host advisory checks.
- Proof and hook execution consume Manager-coordinated capacity. This document
  authorizes no compilation until independent review is accepted and execution
  capacity is explicitly queued.
