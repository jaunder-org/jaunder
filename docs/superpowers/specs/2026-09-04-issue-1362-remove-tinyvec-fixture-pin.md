# Remove Temporary Tinyvec Fixture Pin

Issue: #1362

## Outcome

Remove the direct tinyvec workaround from `rendered-html-compiler-boundary` now
that tinyvec has released the upstream `alloc`-without-`std` fix. The external
fixture declares only `common` directly and proves Jaunder's public/private
compiler boundary without compensating for a transitive dependency; its existing
copy of the repository `Cargo.lock` continues to anchor transitive versions.

## Change

- Remove the temporary `tinyvec = "=1.11.0"` dependency and its explanatory
  comments from the manifest generated by
  `xtask/src/steps/rendered_html_compiler_boundary.rs`.
- Remove the unit assertion that requires the generated manifest to contain that
  pin.
- Keep `common = { path = …, default-features = false }` as the fixture's only
  direct dependency.
- Do not add a replacement tinyvec constraint, Cargo patch, production
  dependency, feature, lockfile, retry, or fallback.

## Preserved contracts

- The fixture remains outside every workspace and continues to copy the
  repository `Cargo.lock`, exercising ordinary downstream feature compilation
  against the repository's anchored dependency graph.
- The positive fixture still compiles against `common` with default features
  disabled.
- Raw `RenderedHtml` construction remains rejected as private.
- The test-support fixture helper remains rejected outside test builds.
- Existing diagnostic classification and reporting remain unchanged.

## Acceptance

- The generated fixture manifest contains no direct tinyvec dependency and still
  names `common` with default features disabled.
- The compiler-backed positive, raw-constructor privacy, and test-support
  confinement contracts all pass against the repository-lockfile-anchored
  dependency graph after the direct fixture dependency is removed.
- Repository production manifests, features, and dependencies are unchanged.
- The repository gate passes.
