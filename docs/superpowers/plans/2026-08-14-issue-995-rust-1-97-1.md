# Rust 1.97.1 Pin — Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with `jaunder-iterate`
> (delegating individual tasks to a subagent via `jaunder-dispatch` when
> useful). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the cache-dependent mutable Rust channel with an exact 1.97.1
pin and keep every warning-denying compiler surface green.

**Architecture:** `rust-toolchain.toml` names the exact release consumed by
local tooling and Fenix; `flake.nix` authenticates that release's manifest. The
five test assertions newly rejected by Clippy migrate mechanically in the same
commit because the pin cannot pass independently. The rebuilt host Clippy
derivation also uses Cargo's development profile: Crane's release-profile
default conflicts with `--all-targets`, which activates the test-only
`cheap-kdf` feature and correctly trips its optimized-build guard.

**Tech Stack:** Rust 1.97.1, Clippy, rustfmt, Fenix, Nix, `cargo xtask`.

**Spec:**
[`2026-08-14-issue-995-rust-1-97-1.md`](../specs/2026-08-14-issue-995-rust-1-97-1.md)

## Review header

**Scope — in:** exact toolchain channel and manifest hash, five `assert_eq!`
migrations, host Clippy development profile, static compiler checks, full local
shipping gate.

**Scope — out:** `flake.lock`, dependencies, lint suppressions, runtime
behavior/tests, changelog, domain documentation, ADRs.

**Tasks:**

1. Pin Rust 1.97.1, migrate the five assertions, prove every Rust 1.97.1
   compiler surface, run the per-commit gate, and commit the atomic change.

**Shipping:** after Task 1 is committed, reviewed, and checked off, archive the
design artifacts, commit that final tracked state, and run the complete shipping
gate on the clean tree.

**Key risks/decisions:**

- The channel and hash move together; accepting either alone leaves the build
  unusable.
- The pin and assertion migrations form one commit because Rust 1.97.1 Clippy
  denies the existing equality assertions.
- Local shell PATH may still point at Rust 1.95.0 after the flake edit. Nix
  Clippy derivations are authoritative for application host/Wasm code; the
  already-built exact 1.97.1 toolchain verifies the separate `tools/` and
  `xtask/` workspaces in this cycle.
- A clean Rust 1.97.1 host Clippy rebuild exposed a pre-existing conflict: Crane
  adds `--release`, while `--all-targets` activates the test-only `cheap-kdf`
  feature whose release guard intentionally fails. Set only the host Clippy
  derivation's `CARGO_PROFILE` to `dev`; production package builds remain
  release-mode and retain the guard.
- No lint suppression is permitted. Any additional Rust 1.97.1 warning is fixed
  at source.

## Global Constraints

- Preserve the configured `wasm32-unknown-unknown` target and all existing
