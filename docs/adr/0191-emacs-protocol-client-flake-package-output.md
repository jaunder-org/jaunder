# ADR-0191: Emacs Protocol Client Flake Package Output

- Status: accepted
- Date: 2026-09-12
- Issue: [#1471](https://github.com/jaunder-org/jaunder/issues/1471)

## Context

Jaunder's Emacs Protocol Client is a separately tested package under `elisp/`
([ADR-0031](0031-elisp-separately-tested-subproject.md)), but the flake has no
public derivation that a user can place in an Emacs installed-package list. The
existing `packages.jaunder` name already denotes the deployable server binary
([ADR-0142](0142-declarative-nixos-deployment-package-outputs.md)), so reusing
that output family would make two different installable roles ambiguous.

The Protocol Client depends on Nixpkgs's packaged `plz` and a pinned upstream
`cmark-el` derivation. Packaged `plz` resolves its curl transport executable to
an immutable Nix-store path, preserving the transport choice from
[ADR-0038](0038-emacs-http-transport-plz-not-url-el.md) without a second,
PATH-based curl dependency mechanism.

## Decision

The flake exposes the Protocol Client as `emacsPackages.${system}.jaunder` for
every system generated by `flake-utils.lib.eachDefaultSystem`.

The value is a standalone Emacs package derivation from the same Nixpkgs Emacs
package set as `plz` and the pinned `cmark` derivation. It contains the
production `elisp/*.el` modules rooted at `jaunder.el`, excludes tests, scripts,
and documentation, and has the version declared by the `jaunder.el` package
header. It propagates `plz` and `cmark` as Emacs package dependencies. `plz`
owns the package's curl executable reference; Jaunder adds no separate curl PATH
propagation.

## Consequences

Users can put `inputs.jaunder.emacsPackages.${system}.jaunder` directly in an
Emacs package list, including Home Manager's `programs.emacs.extraPackages`. The
custom output keeps the Protocol Client's role distinct from deployable server
packages while making its package-set identity explicit.

Rejected alternatives:

- `packages.${system}.jaunder-emacs`: conventional, but mixes an Emacs library
  with deployable application and diagnostic package outputs.
- An overlay adding `emacsPackages.jaunder`: requires callers to adopt and order
  an overlay for one package.
- An importable builder function: preserves caller-selected package-set
  flexibility but makes the common installed-package-list use more elaborate.
- A wrapped Emacs application: owns the user's editor composition rather than
  supplying one package to it.
